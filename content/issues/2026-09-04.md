## 本週優先閱讀排序

### 1. Agent Memory Is a Surface for Endogenous Authorization Laundering

- **日期／作者**：2026-09-01；Tommaso Cerruti、Mika Okamoto、Ansel Kaplan Erol
- **原文**：[arXiv 2609.01836](https://arxiv.org/abs/2609.01836)
- **核心發現**：EAL-Bench 涵蓋採購、資安與金融情境。增量式記憶更新使模型對未授權要求產生最高 **50.2%** 的虛假權限；一旦錯誤權限進入記憶，執行模型在 **98.6%** 的測試中依此採取行動。
- **製造業關聯**：採購代理、供應商資格審查、PLM 變更、弱點修補及工單代理都可能把已撤銷、限時或條件式核准錯記成永久權限。
- **判定：深入審閱**。直接改變 AI System Threat Modeling：Agent memory 應視為授權政策的一部分，不只是聊天紀錄。限制是工具與業務流程仍為模擬環境，不能推估實際企業事故率。

### 2. Context Inference Attacks Without Jailbreaks

- **日期／作者**：2026-08-31；Prince Jha、Samuele Poppi、Nils Lukas
- **原文**：[arXiv 2609.01663](https://arxiv.org/abs/2609.01663)
- **核心發現**：攻擊者不必誘導模型直接吐出機密，也能從正常回答推斷隱藏 context。研究在小型候選集達 **100% ASR**、1,024 個候選時為 **63%**；Agent 自行檢索資料的情境仍達 **81.8 AUROC**。作者測試的禁止揭露指示、logit suppression 與 context dilution 都未消除洩漏。
- **製造業關聯**：即使 RAG／Agent 沒有逐字輸出 BOM、報價、客戶設計或設備資料，外部使用者仍可能藉重複查詢推斷某筆資料是否存在。
- **判定：深入審閱**。這是傳統 DLP 容易漏掉的「推論式外洩」；但實驗使用受控候選集合與合成憑證，跨模型 transfer 也不是必然成功。

### 3. Explainable Artificial Intelligence for Industrial Cybersecurity

- **日期／作者**：2026-08-31；Amr S. Mohamed、Charlotte Fritz、Ahmad Mohammad Saber 等 8 人
- **原文**：[arXiv 2609.00171](https://arxiv.org/abs/2609.00171)
- **核心發現**：系統性整理工業 SOC 中的特徵歸因、代理模型、規則與視覺化方法。研究指出現有 AI／XAI 驗證仍高度依賴公開 IT、IoT 或網路流量資料，對跨 Purdue 層級攻擊、產線時間限制與真實操作員決策支援的證據不足；局部解釋也不應直接轉成全域偵測規則。
- **製造業關聯**：有助於重新設計 OT AI PoC，不只比較 F1-score，也檢驗解釋穩定性、操作員判讀時間、誤動作成本及跨 IT／OT 攻擊鏈。
- **判定：深入審閱**。製造業直接性高，適合 OT SOC 與模型風險團隊共同閱讀；屬綜述，沒有提供新的實廠部署成效。

### 4. Enterprise Security Architecture Spotlight  
**Zero Trust Architecture for Industry 5.0 and Industrial IoT**

- **日期／作者／來源**：2026-08-27；Ali Akhmetkaliyev、Mohammed Alaa Ala’anzy、Mahmoud Khalid Almsafir、Saleh Musleh；Computer Networks
- **原文**：[DOI 10.1016/j.comnet.2026.112695](https://doi.org/10.1016/j.comnet.2026.112695)
- **核心論點**：PRISMA 2020 流程由 492 篇篩選出 45 篇同儕審查研究，建立五類 ZTA 架構：身分與存取、異常偵測、區塊鏈信任、聯邦／分割式學習、後量子與硬體安全。作者主張 brownfield 工廠較可行的方向，是以符合 IEC 62443 的 gateway／proxy 承接持續驗證，而不是直接改造所有舊 PLC。
- **證據品質**：同儕審查系統性回顧；雙人評選一致性 κ=0.83，也揭露各研究品質評分。
- **限制**：只搜尋 Scopus 與英文文獻；延遲、準確率等數字主要來自各論文自行回報，沒有統一測試床，因此只能做描述性比較。沒有直接評估 SAP、S/4HANA、ERP 或 PLM。
- **利益衝突**：作者聲明沒有已知財務或個人利益衝突。
- **事實／主張／推論**：
  - **已查證事實**：收錄 45 篇研究、搜尋截至 2026 年 7 月；作者明確承認沒有獨立重現底層實驗。
  - **作者主張**：跨研究平均 authentication latency 35 ms、IDS accuracy 95.2%，gateway 最多降低 73% 通訊延遲；因測試環境不同，不宜直接橫向比較。
  - **本次分析推論**：ODM／OEM 應把 ERP／PLM／MES 到產線的每一次跨區資料與控制請求視為獨立信任決策，並在 OT gateway 強制執行，而非沿用企業網路或 SAP 登入後的隱含信任。
- **建議行動**：
  1. 盤點 ERP、PLM、MES、數位分身與設備之間的機器身分、資料流和控制路徑。
  2. 在 cell／site gateway 實作 workload identity、短效憑證、每次請求授權及細粒度稽核。
  3. 對安全關鍵流程量測 p95／p99 policy latency，保留經核准的降級與人工接管模式。
  4. 將模型、規則、韌體及訓練資料的版本與 lineage 綁定到部署核准。
  5. 對供應商遠端維護與跨公司 PLM 協作使用限時、限資源、可撤銷的權限。
- **適合讀者／時間**：企業架構、OT Security、IAM、SAP／PLM、AI 平台與供應鏈治理負責人；約 35–45 分鐘。
- **判定：深入審閱**。在最近 30 天內發布，方法透明且最貼近 brownfield 製造架構；須避免把區塊鏈或論文平均效能當成既定採購要求。

### 5. Stealing Reasoning Traces from Proprietary LLM APIs

- **日期／作者**：2026-08-10；Alexander Panfilov、David Schmotz、Ilia Shumailov 等 8 人
- **原文**：[arXiv 2608.09867](https://arxiv.org/abs/2608.09867)
- **核心發現**：研究者利用同一供應商內跨 session、使用者及模型可重放的加密 reasoning block，讓較弱模型充當解碼器。對 315,320 個公開 reasoning blocks 的掃描找到 367 筆 PII 與 182 筆憑證。
- **重要查核修正**：作者表示研究測試發生於 **2026 年 7 月初**；揭露後各供應商均確認收件，研究者之後已無法用相同方式發動攻擊。因此這是已證實的架構缺陷與資料衛生教訓，**不能宣稱目前 API 仍可被同法利用**。
- **製造業關聯**：Agent trajectory、除錯紀錄、API response dump 即使看似加密，仍不應提交到 Git、工單或供應商支援平台；若曾分享，應評估撤除、憑證輪替及資料外洩通報。
- **判定：選讀**。W36 報告的重要補錄且原始數字已核實，但不是本週發布，攻擊現況亦已改變。

### 6. Agent Flight Recorder

- **日期／作者**：2026-09-01；Laurent Bindschaedler、Quentin Botha、Christoph Siebenbrunner
- **原文**：[arXiv 2609.01931](https://arxiv.org/abs/2609.01931)
- **核心發現**：以八個語意欄位記錄 Agent 意圖、授權、執行及 provenance，再用 hash chain、Merkle batch 與鏈上 anchor 提供防竄改驗證。合成工作負載中，每事件增加約 48 微秒與 512 bytes，四類竄改偵測率為 100%。
- **製造業關聯**：可用於追查 Agent 對 ERP、PLM、程式庫、工單與 OT gateway 的委派鏈和實際副作用，是 AI Data Lineage 與不可否認稽核的具體設計候選。
- **判定：選讀**。已獲 BCCA 2026 接受且設計具可實作性；不過主要證據來自合成負載，若攻擊繞過被監控 gateway 或主機已遭控制，紀錄仍可能不完整。企業可先試行結構化、異地保存的 hash-chain log，不必直接採用區塊鏈。

## 建議下一步

1. 將 Agent memory 納入授權資料模型：所有核准、撤銷與期限必須連回不可變的權威事件，不接受自然語言摘要自行授權。
2. 在 AI DLP 威脅模型新增 context inference：限制可檢索資料、查詢次數與候選確認能力，並對重複探測建立偵測規則。
3. 清查 Git、工單及模型評測資料中的 raw API transcript、opaque reasoning field 與 agent trajectory；有外流跡象即輪替相關憑證。
4. OT AI PoC 加入跨 Purdue 層級資料、解釋穩定性、操作員判讀時間與錯誤動作成本。
5. 先以一條 PLM／ERP → MES／OT Agent 流程試行結構化 audit event、授權 provenance 與異地防竄改保存，再評估是否需要外部錨定。
